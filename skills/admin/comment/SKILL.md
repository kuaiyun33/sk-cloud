# admin 注释

目录、命名、接口边界以 `sk-cloud-admin` 为准。注释写法以本技能为准。正反例见 [EXAMPLES.md](EXAMPLES.md)。

## 原则

- 只补充名字、键含义、边界和维护约束，不复述代码
- 能一行写完的不拆多行；标题用名词或短动宾
- 禁止「用于」「以便」「这里是」「以下是」「例如」
- 不给显而易见的局部变量、简单条件、模板结构补噪音
- 中文全角标点；短语末尾不加句号
- 英文专有名词保持原文，前后不强制空格
- 紧贴被说明的声明，中间不留空行
- 随代码更新；禁止过期说明和被注释掉的旧代码
- 注释不得把错误归属解释成合理归属
- 新增可复用能力时只说明稳定语义，不写调用方小作文

## 文件头

默认不写。文件职责不靠文件名和导出项能看懂时，允许在 `import` 前或后写 1～2 行模块注释。禁止在 `import` 与第一个顶层声明之间插多段说明。不写作者、时间、版本、变更记录。

## 必须写

| 对象                              | 形式                     |
| ------------------------------- | ---------------------- |
| 导出的公共类型、接口、类                    | 声明上一行单行 JSDoc          |
| 后端协议类型                          | 标注「后端原始字段」             |
| 前端标准类型                          | 标注「前端标准字段」             |
| 常量、配置对象、关键状态                    | 单行 JSDoc               |
| 导出函数、公共 composable、store action | 完整 JSDoc               |
| 持久化状态                           | 写清缓存语义                 |
| 数值                              | 单位写在注释里，可用尖括号          |
| 布尔                              | 「是否 xxx」，不要「控制 xxx 开关」 |

类型字段仅在含义、单位、边界不明显时写。禁止在类型注释里写业务流程、接口 URL、调用链。大型配置至少给导出项或顶层键补短注释。外部协议值、缓存键、请求头、路由路径写明语义，不解释取值来源。

## 函数 JSDoc

- 摘要：短动宾短语
- 摘要行禁止末尾追加括号。约束另起一行，前缀 `注：`，与摘要、`@param` 各空一行
- `注：` 极短；翻译函数名或重述参数则删除，不留空 `注：`
- 类型/接口单行 JSDoc 同样禁止末尾括号；需要补充时改多行并以 `注：` 另起一行
- 有参数必须 `@param`，顺序与形参一致
- 有返回必须 `@returns`；无返回写 `@returns void`；不重复签名已表达的类型
- `@param`/`@returns` 里的值约束、枚举、范围、示例可保留行内括号
- 复杂对象参数用缩进 `-` 列键
- 异常边界不明显时可 `@throws Error`
- 内部小函数名称和签名已够清晰时可不写

底层 store 接收外部 loader 或标准化数据时，注释要体现边界。派生状态用单行注释说明结果含义，不描述 computed 实现。不在注释里解释页面业务流程。

## Vue

- `<template>` 禁止 `<!-- 注释 -->`，也不用模板注释说明 UI/交互/无障碍
- `<script setup lang="ts">` 内遵循本文件 TS 规则
- `defineProps`/`defineEmits` 类型复杂时抽出接口并给接口写注释
- 组件顶部禁止「页面说明」类注释；路由标题或组件名能表达时不重复
- 样式仍走独立 `.less`，不在注释里为内联样式找理由

## 行内与分区

行内只用于安全边界、兼容边界、非显而易见算法。禁止翻译 `if`/`return`/变量名。`TODO`/`FIXME` 必须带明确事项。

默认不用分区。同一文件两段以上清晰职责且较长时，才用三行式分区，标题用名词短语。禁止「分割类」「以下接口」「业务逻辑功能」。
