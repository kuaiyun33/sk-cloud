# 项目记忆协议

记忆只存在**当前业务仓库**的 `.sk-cloud/memory/`，不写进公开技能包，不写进 Grok 个人 Memory。找不到仓库根就只做事、不记。

仓库根判定见 [WORKSPACE.md](WORKSPACE.md)。目录不存在时，第一次写入用脚本创建。

## 文件

| 文件 | 谁读 |
| --- | --- |
| `INDEX.md` | 任何改动开工必读 |
| `php.md` `admin.md` `web.md` `i18n.md` `gate.md` | 进入对应面再读有效全文 |
| `archive.md` | 作废/核对历史时才读，开工禁止读 |

脚本（插件根 `scripts/memory.py`，仓库内常见 `.cursor/skills/sk-cloud/scripts/memory.py`）：

```bash
python3 scripts/memory.py --cwd . status
python3 scripts/memory.py --cwd . index
python3 scripts/memory.py --cwd . add --surface admin --object "操作列" --rule "禁止橙色，用 text 按钮" --source explicit
python3 scripts/memory.py --cwd . forget admin-001 --reason "取消"
python3 scripts/memory.py --cwd . delete admin-001 --reason "删除"
python3 scripts/memory.py --cwd . sync
```

优先用脚本，保证 id 和 INDEX 一致。`add`/`forget`/`delete` 默认会单独提交 `.sk-cloud/`；当前分支只超前这一笔时再 push。`delete` 与 `forget` 同义。脚本找不到时按本文件格式手写，并重建 INDEX，随后必须 `sync`。

## 读（不做等于没记）

1. 开工读 `INDEX.md`。没有该文件 = 无记忆，不要报错。
2. 变更落在哪一面，再读那一面的 md。跨面任务读多面。
3. 做事时用到某条，必须点名 id，例如：按记忆 `admin-001`。
4. 收工自检：是否违反有效记忆；本面有有效条却一条都没引用，视为没读，补读后再交付。
5. 技能正文与记忆冲突：遵守技能正文，记忆条标冲突待改，不按违法记忆写代码。

## 什么能记

必须同时能回答：面、对象、必须/禁止/默认、范围。

- 可复用的颜色/token、格式、命名、禁止项、默认交互、注释模板
- 跨页面还会再用
- 用户要长期按这个做（怎么说都行）
- 或要求本身已是稳定规则，且智能写入闸门全过

## 什么不能记

- 只针对当前页、这一次 bug、先这样回头再说
- 个人对话风格（回复长短）
- 技能里已有的同义规则（去重，不重复记）
- 范围说不清（「不要那种颜色」）
- 把特例写成全局（「这个危险按钮用红」≠「按钮都用红」）
- 与技能硬规则冲突的原文（「写死 8px」应改成「用对应圆角 token」，改不成则拒绝）

## 对人（不设口令）

用户怎么说都行。禁止教词、纠正用词、要求改口、甩词表、把内部命令念给用户听。

听意思，不听关键词。短句、口头禅、改口、说删掉/去掉/算了/就这样，都要接住。

内部只分意图（用户不必知道这些名字）：

| 意图 | 判断 |
| --- | --- |
| 写入 | 以后都按这个做 |
| 作废 | 以前记下的那条不要了 |
| 覆盖 | 同一件事改成新说法 |
| 同意 | 认可刚才那句复述：短应、接着往下说都算 |
| 拒绝 | 只要这一次，或先别记 |

沉默不算同意。不要等某个指定词才动手。

删的是文件/按钮/接口 → 只改代码。针对「刚才记下的那条」→ 作废记忆。分不清就问一句人话：「是把这条偏好从项目里拿掉，还是只改眼前这个？」不要连续追问，不要用「作废记忆」这种词逼用户选。

「刚才那条」：本轮刚写下的 id；对不上或有多条，用人话列出候选再拿掉。

## 写入闸门

**已经说清要长期按这个做，或要拿掉某条**  
用一两句人话复述（对象 + 必须/禁止 + 范围），然后立刻写或拿掉。不必再问「可以吗」。

**拿不准是不是要长期记**  
同时满足才开口：

1. 能写成一句可执行的必须/禁止/默认
2. 落在 php / admin / web / i18n / gate 之一
3. INDEX 和技能正文没有同义条
4. 范围能定到「面 + 对象」；不能定则先问
5. 不是当前文件的一次性实现
6. 不与技能硬规则冲突

用人话问，不要表单：

```text
操作列以后都不用橙色，用文字按钮。我记到这个项目里，换电脑拉仓库也还在。可以吗？
```

同意 → `add`。只要这一次或先别记 → 不写。改范围 → 改完再问。没表态 → 本轮不写。

默认最窄：当前模块或组件类型。用户明显是到处都一样，才放到本面全局。

## 对人怎么说

| 时机 | 对人 | 禁止 |
| --- | --- | --- |
| 复述 | 一两句人话 | 「拟写入项目记忆」、字段列表、「要写入吗？」 |
| 已记下 | 记下了什么；换电脑能不能带走 | 对用户念 `switch_computer`、`source`、口令名 |
| 已拿掉 | 那条已经去掉了 | 要求用户改口说「忘掉」 |
| 还没到远程 | 这台记下了，远程还没有，换电脑会丢；我去推 | 假装已经能换电脑 |
| 编号 | 可带一句 `admin-001`，方便以后说删哪条 | 把编号当唯一沟通方式 |

脚本输出给自己看。`switch_computer` 是 `ok` 才告诉用户换电脑能带走。

## 作废

要拿掉某条：`forget <id>` 或 `delete <id>`（同义）。进 `archive.md`，INDEX 立刻不再出现。读路径看不到才算拿掉。

改口覆盖：先 forget 旧 id，再 add，新条「取代」写旧 id。禁止两条对着干的有效规则并存。用户改口时直接覆盖，不必先说某个词。

## 存在哪、换电脑

两样东西分开：

| 东西 | 在哪 | 换电脑 |
| --- | --- | --- |
| 读写协议 | 公开插件 `sk-cloud` | 新电脑再装一次插件 |
| 记忆正文 | **当前业务仓库** `.sk-cloud/memory/` | 克隆或拉取**这个项目**的 git 远程 |

记忆不进公开技能包，不进 Grok 个人 Memory，不进本机其它目录。找不到仓库根就只做事、不记。

写入后本机立刻能读。`add`/`forget` 必须看脚本输出的 `switch_computer`：

- `ok`：已在业务仓库远程，换电脑 `git clone` / `git pull` 即可
- `blocked`：只在这台电脑。先处理 `reason`，再跑 `sync`。禁止对用户说已经能换电脑带走

只提交 `.sk-cloud/`，不要把当时其它脏文件塞进同一笔。分支比上游还多其它本地提交时**不自动 push**，避免把未完成的业务改动推上去。

| 情况 | 记忆还在吗 |
| --- | --- |
| 同一台电脑、同一仓库 | 在，读 INDEX |
| 换电脑、克隆/拉取同一业务仓库且 `.sk-cloud/` 已在远程 | 在，跟着项目走 |
| 只装了 sk-cloud 技能、没拉这个项目 | 不在（技能没有项目偏好） |
| 这台写了但 `switch_computer: blocked` | 只在这台电脑，换电脑会丢 |
| 电脑坏了、远程有这份仓库 | 从远程再拉回来 |
| 两台电脑都在写记忆 | 先 `git pull` 再写；冲突时保留双方条目、重建 INDEX，禁止两条 active 对着干 |

换电脑步骤：

1. 克隆或拉取**业务仓库**（与代码同一远程）
2. 确认 `.sk-cloud/memory/INDEX.md` 在
3. 安装 `sk-cloud` 插件（只有协议；记忆正文不在插件里）
4. 开工读 INDEX

禁止把 `.sk-cloud` 写进 `.gitignore`。

## 场景速查

| 情况 | 做 |
| --- | --- |
| 「操作列别用橙色，以后都这样」 | 人话复述后 `add` |
| 「就这么着」「记一下」 | 同上 |
| 「金额一律两位小数」PHP 已有 Money | 不重复记；admin 展示若缺口只记 admin |
| 「这个弹窗先改抽屉」 | 不记 |
| 「营销可以用品牌橙」但旧条禁止橙 | 覆盖：forget 旧条再 add |
| 「圆角就 8px」 | 改写成 token；改不成则拒绝记 |
| 「不要那种颜色」 | 不记，先问范围 |
| 「这个危险按钮用红」 | 不升格为全部按钮 |
| 「以后注释都按这段」 | 可记，存模板到示例 |
| 「橙色那条删掉 / 取消 / 不要了」 | forget |
| 「删除这个按钮」 | 改代码，不动记忆 |
| 「刚才那个去掉」 | forget 本轮那条；多条则用人话列出来 |
| 「这里不要 Tabs」 | 默认只记当前模块 |
| 「回复短一点」 | 不记 |
| 找不到仓库根 | 不记，说明原因 |
| 记忆目录不存在 | 第一次 `add`/`index` 创建 |
| 本面有记忆但交付未引用 | 未读，补读 |
| 换电脑 | 拉业务仓库；看 `status` 的 `switch_computer` |
| 写完但没上远程 | 跑 `sync`；仍 blocked 则说明 reason，不要假装已同步 |

## 条目字段

`id` 面-三位序号；`状态` active / superseded；`面`；`对象`；`范围`；`规则`（必须可执行）；`来源` explicit / inferred；`取代`；`写入` 日期。可选示例代码块。
