# PHP 注释

职责归属、查询位置、字段边界以 `sk-cloud-php` 为准。注释写法以本技能为准。完整正反例见 [EXAMPLES.md](EXAMPLES.md)。

## 原则

- 只补充名字、键含义、字段边界和维护约束，不复述代码
- 能一行写完的不拆多行；标题用名词或短动宾，不写作文
- 禁止「用于」「以便」「这里是」「以下是」「例如」等铺垫
- 中文全角标点；短语末尾不加句号
- 英文专有名词保持原文，前后不强制空格
- 紧贴被说明的声明，中间不留空行
- 禁止提交被注释掉的旧代码；注释随代码更新

## 文件头

每个 PHP 文件必须 `declare(strict_types=1);`。`declare` 与 `namespace` 之间禁止写注释。不写作者、时间、版本、变更记录。类型职责写在声明紧上一行。

## 必须写的注释

| 对象 | 形式 |
| --- | --- |
| 类/接口/trait/enum | 单行 PHPDoc，只写稳定职责 |
| 常量、关键属性 | 单行 PHPDoc；有原生类型时不重复类型 |
| public/protected 方法 | 完整 PHPDoc |
| 控制器 action、模型查询/写入、验证器公共方法、底座公共方法 | 完整 PHPDoc |
| 模型 `$casts` 每一行 | 行尾 `//` 字段说明，按列对齐 |
| 验证器 `$rule` `$message` `$scene` | `@var` + 极短语义 |
| 数值 | 单位写在注释里，可用尖括号 |
| 布尔 | 「是否 xxx」 |
| `@var` | 仅数组结构、框架约定属性、动态属性无法靠原生类型表达时 |

空异常类可一行声明，不强制类注释。抽象类和接口写契约名词，具体实现写实现职责。

## 方法 PHPDoc

- 摘要：短动宾短语
- 摘要行禁止末尾追加括号补充。内部步骤、约束、场景或数据范围另起一行，前缀 `注：`，与摘要行、`@param` 各空一行
- `注：` 极短，只补方法名和摘要无法表达的关键约束；翻译方法名或重述参数则删除
- 有参数必须 `@param`，顺序与形参一致
- 必须 `@return`；无返回写 `@return void`；不重复签名已表达的类型
- `@param`/`@return` 描述里的值约束、枚举、范围、示例可保留行内括号
- 异常边界不明显时写具体 `@throws`
- private 若名称和签名已够清晰，可只写单行摘要；复杂数组或多个参数仍写完整 PHPDoc
- 复杂数组参数/返回在注释中列关键字段，字段保持 snake_case

控制器类只写入口职责，action 只写请求入口语义，禁止描述 SQL、分页和组装。控制器里出现查询时按 `sk-cloud-php` 移入模型，不用注释解释。

## 行内与分区

行内注释只用于安全边界、兼容边界、算法边界、框架特殊约定。禁止翻译 `if`/`return`/变量名。`TODO`/`FIXME` 必须带明确事项。

默认不用分区。同一类两段以上清晰职责且文件较长时，才用三行式分区，标题用名词短语。禁止「分割类」「以下接口」「业务逻辑功能」。

## 完成检查

短、准、无废话；`declare` 与 `namespace` 之间无注释；类、关键属性、公共方法已补中文注释；public/protected 含 `@param` 与 `@return`；casts 行尾对齐；验证器 `@var` 完整；无注释掉的旧代码。
