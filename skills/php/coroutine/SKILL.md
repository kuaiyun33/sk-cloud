# 协程与并发

语言层走 `php` 技能。架构与复用走 `sk-cloud-php`、`sk-cloud-php-reuse`。Parallel 细节、验证清单见 [REFERENCE.md](REFERENCE.md)。

## 原则

协程只用于 IO 密集并发，不用于 CPU 密集。协程优化等待时间，不改变职责。根因是查询没进模型、缺索引、重复逻辑或职责错位时，先修根因。

普通控制器、普通模型 CRUD、简单配置读取默认不引入协程。引入前必须说明：并发对象、并发收益、共享资源、失败策略、最大并发数。

禁止为了压 bug、绕开慢查询、绕开阻塞或兼容脏数据而引入协程。协程代码必须能降级为清晰串行逻辑；串行都说不清，禁止并发化。

## 事件循环

必须用 Workerman/webman 官方协程。禁止业务代码手写 PHP `Fiber` 调度器，禁止 `go()`、`Swoole\Coroutine\run()` 或绕开 Workerman 事件循环的启动方式。

多独立任务优先 `Workerman\Coroutine\Parallel`。事件循环驱动只在进程配置层决定，禁止在控制器、模型、Support 或 worker 业务方法里临时切换。

现有 `Workers\process\Process` 按环境选择 `Workerman\Events\Swoole` 或 `Workerman\Events\Fiber`，新增进程沿用统一入口。

Fiber 不会把阻塞 IO 自动变非阻塞。Swoole/Swow 有扩展行为差异；启用一键协程化前确认部署、连接池、安全和压测。

## 允许

- 多个互不依赖的 HTTP/API 并发
- 多个插件/事件配置、文件元信息并发读取后汇总
- 队列、计划任务、后台导出中明确 IO 等待且可切分
- WebSocket 多个独立回调并发（必须限并发和处理异常）
- 大目录扫描、批量文件、库结构导出等可拆分任务（必须有上限）
- 启动期加载多个互不依赖资源，且失败策略清晰

## 禁止

- 控制器为了「快一点」包一层协程
- 用协程掩盖未归位的慢查询
- 数据库事务内部开并发协程
- 多协程共享同一个 DB/Redis/socket/文件句柄/第三方 SDK 实例
- 多协程同时写同一条订单、余额、库存、任务状态、系统配置或日志聚合结果
- 协程读写请求态 static、global 或单例临时属性
- 用 `sleep()`/`usleep()` 修竞态
- 吞异常、默认空数组、默认成功来维持主流程
- 在并发结果里临时适配多套旧状态来源

金额、订单、余额、库存、账单、支付、退款、权限和状态流转的写操作默认不并发。需要并发读再写时：先并发读，回到串行后统一校验和写入。并发写入必须有幂等键、唯一约束、乐观锁、悲观锁或原子更新。部分成功必须是业务允许的稳定状态，否则整体失败并回滚或明确补偿。协程不能改变状态机顺序。

## 注释

协程方法必须说明并发对象、并发上限、失败策略和结果结构。并发上限用常量，注释写业务依据（外部限流、文件 IO、连接池大小）。不写「使用协程提高性能」。为兼容框架或官方组件时注明对应组件和运行边界。

完成后必须写明：协程原因、并发上限、共享资源、失败策略、验证结果。
