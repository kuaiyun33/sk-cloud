# 协程细节

## 上下文

请求态数据通过参数、局部变量、`Webman\Context` 或框架请求对象传递，禁止放入 global/static。

协程内部临时上下文可用 `Workerman\Coroutine\Context`，不得替代模型参数、业务参数和显式返回值。

`request()`、当前管理员、当前用户、trace_id、权限、租户等禁止缓存到 static。跨协程必须显式传参。协程结束后不得留下影响下一请求或下一任务的上下文。

长生命周期 worker 的对象属性只保存稳定配置、连接池、回调表和连接集合。

## 资源与连接

数据库、Redis、Cache 必须用项目已有连接池或官方协程安全组件。不确定是否协程安全的第三方 SDK 默认不安全，串行或封装隔离。

每个协程任务自己获取连接，禁止把外层已开事务的连接传入多个协程。共享写资源必须用锁、队列、单协程归并写入或数据库原子条件。

并发数必须有上限，禁止按用户输入、表数据量、文件数量无限创建。上限用常量表达。外部 HTTP/API 必须设超时，超时进入异常或失败结果。完成后释放临时资源，不把大数组、大响应体、文件内容留在长生命周期对象。

## Parallel

必须传入合理并发上限。`Parallel::add()` 闭包必须是小任务，输入明确，返回结构稳定。闭包禁止依赖外层可变引用；需要的数据用 `use` 传入只读值。

`Parallel::wait()` 后必须读取并处理异常集合。结果按 key 或明确字段归并，禁止靠返回数组自然顺序表达业务关系。

子任务失败必须记录子任务标识、输入摘要和异常原因。允许部分失败时，返回结构显式包含成功列表、失败列表和失败原因。不允许 `array_filter($parallel->wait())` 后直接忽略失败，除非业务明确允许且日志完整。

## 阻塞调用

Fiber 下普通阻塞 IO 不会自动让出，不能假设协程会提升阻塞代码性能。优先用官方支持的 HTTP、Redis、数据库和连接池。

无法确认是否非阻塞的 SDK、文件操作、压缩、加密、大量 JSON 编解码和 shell，默认按阻塞处理。阻塞操作不得放在 HTTP 热路径的协程中扩大影响面。计划任务和队列中确需阻塞等待时，评估 worker 数量、超时、重试和堆积风险。

## 错误处理

协程异常必须向上暴露或进入明确失败结果，禁止吞异常。必须有整体失败策略：全部失败、部分成功、快速失败或降级。降级必须是业务确认的结果，不得用空数组、空字符串、0 或 false 假装成功。

错误日志必须包含批次 ID、任务名、子任务 key、异常类名和异常消息。修复必须以真实日志、数据、调用链和可复现步骤为依据，禁止猜并发数或加等待。

## 验证

引入后必须验证串行等价结果。必须覆盖：单个失败、多个失败、全部失败、超时、空数据、大数据量、重复执行。涉及数据库/Redis/文件/外部 API 时验证没有串写、连接污染、上下文污染和重复写入。涉及请求上下文时验证连续请求不串用户、权限、trace_id。涉及常驻 worker 时验证多轮后内存不持续增长。性能收益必须用耗时日志、压测或任务记录证明。

## 变更

新增前搜索 `Workerman\Coroutine\Parallel`、`Workerman\Events`、`Context`、`sleep(`、`usleep(` 和同类任务实现。改并发数前确认连接池、外部限流、任务数量和失败率。改事件循环配置前确认 HTTP、WebSocket、队列、计划任务、数据库、Redis 和 HTTP client 兼容。禁止只靠降低并发、加锁或加 sleep 掩盖问题。
