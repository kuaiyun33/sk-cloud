# 表、字段与 MCP

协议字段命名见 [LAYERS.md](LAYERS.md)。casts 见 [MODEL.md](MODEL.md)。

## MCP 数据源

连接以当前环境 MCP **服务名**为准，禁止用本机同名库、`localhost` 或 `bootstrap/constants.php` 里的库名替代。host、端口、库名只存在 MCP 配置里，不写进技能。

| 用途 | MCP 服务 |
| --- | --- |
| 新项目主库 | `mysql_new_main`（`mcp__mysql_new_main__`） |
| 新项目日志库 | `mysql_new_log`（`mcp__mysql_new_log__`） |
| 旧项目主库参考 | `mysql_main`（`mcp__mysql_main__`） |
| 旧项目日志库参考 | `mysql_log`（`mcp__mysql_log__`） |

会话没有这些 MCP 工具时，先说明不可用，再按当前 MCP 配置的 host/database/user 等价直连。禁止静默切到本机 MySQL。

工具用途：

- 表清单：`list_tables`
- 字段结构：`describe_table`
- 样本或旧逻辑核对：`fetch_data`
- 复杂 SQL/索引/聚合才用 `execute_query`
- 测试数据优先走项目代码和模型；MCP 直写必须确认是新项目库，禁止写旧库

迁移旧能力：先用旧库 MCP 看表和必要样本，再用新库 MCP 确认是否已有对应表、字段和归属。旧库只理解历史，不作为运行依赖，不把旧字段、旧状态、旧兼容写法不经治理搬进新项目。

MCP 结果只辅助判断。真正的查询、聚合、分页、状态判断必须进模型或明确仓库。控制器、中间件、验证器、worker 禁止直接承载查询。

对比新旧表时同时检查：命名、语义、默认值、索引、外键、时间存储方式，不能只按字段名机械迁移。

## 表前缀

新表统一 `sk_` 前缀；模型 `$table` 不写前缀。

只建当前实际用到的表，不把旧库全量搬迁。迁移优先功能完整，再做轻量优化，禁止过度设计。用户名、插件目录等唯一性不能机械加唯一索引，先确认是否允许跨模块/跨场景重复。

不随意移除外键；有关联的新表要同时考虑被引用表和外键。

## 新增表

新增前确认：业务归属、生命周期、写入入口、读取入口、清理策略、是否走日志库。先查新旧 MCP，禁止没搜索就建平行表。不为「以后可能用」提前建宽表、备用字段表、万能配置表。

表名表达稳定实体或关系，不用 `data` `info` `record` `detail` `extra` 当主语义。

## 新增字段

字段名表达业务语义。禁止用 `type` `status` `value` `config` `remark` 承载多种互斥含义；确实需要时用注释、字典或模型常量钉死边界。

先判断语义：实体属性、关系、状态、统计冗余、快照、日志、运行缓存。不同语义不混进同一字段。

- 状态：固定枚举、字典表、外部平台还是内部流转；casts 和判断与来源一致
- 时间：创建、更新、过期、执行、完成、删除、同步、回调或外部发生时间
- 金额：币种、精度、正负、结算语义；禁止 float；禁止金额与展示文案混存
- JSON：只存结构稳定但列化收益不高的数据；常查/筛/排序/关联的必须拆字段或子表
- 冗余：只用于性能、快照或追溯，并标明权威来源；禁止冗余变成第二套事实

索引来自真实查询、唯一约束或外键，不为所有字段机械加索引，也不漏高频筛选和关联。唯一索引必须确认范围：全局、租户内、用户内、插件内、供应商内。禁止把页面校验当成库唯一规则。

默认值表达业务默认状态，不为少处理 null 随意写空串、0 或空数组。允许 null 只表示未知/未发生/未配置/不适用；空集合或空文本用明确默认值。

软删除、审计、创建人、更新人、来源平台、外部 ID 等横切字段，只有业务会读或追溯时才加。

新增表后同步：模型、casts、状态常量或字典、验证器、迁移说明、调用方查询方法、日志写入边界。新增字段后搜索同名旧字段和近义字段，确认没有第二套命名或第二套状态流转。

## 快照

涉及订单、账单、支付、商品、交付等历史数据：保存当时快照，足以支撑展示、售后和审计。当前配置变更不得改写历史订单。价格、折扣、币种、交付参数要有稳定记录。快照字段归属当前领域，不存其它模块私有资源字段。
